## 答辩叙事

用五段叙事压缩论文：

1. 什么问题真实存在，为什么现在需要解决；
2. 现有方法具体缺什么；
3. 本课题采用什么方法补这个缺口；
4. 实验在什么条件下支持什么结论；
5. 贡献、局限和下一步分别是什么。

每页幻灯片只承担一个论证任务。答辩的目标是让评委理解问题、方法和证据，而不是展示开发过程或所有功能。

## 幻灯片结构

可适配的结构：

- 题目与一句结论；
- 问题与应用场景；
- 现有工作与明确缺口；
- 研究问题或假设；
- 方法/系统总体设计；
- 关键设计选择；
- 实验协议、数据和基线；
- 主要结果；
- 贡献与消融或案例分析；
- 局限与未来工作。

幻灯片检查：

- 第一分钟能说清“做了什么、为什么、如何证明”；
- 每个结果页都标注数据条件、基线和指标；
- 不把未完成计划混入已完成结果；
- 字号、图表和颜色在投影环境中可读；
- 方法与实验总时长满足学校限时。

## 演示风险

准备三层方案：

1. 实时系统演示；
2. 本地录屏或关键流程视频；
3. 静态截图、结果表和手工案例。

演示前检查网络、账号、数据、依赖、字体和设备。固定演示数据，避免现场临时上传或依赖不可控外部服务。演示只覆盖能支持核心贡献的主链路，不在时间有限时展示低价值功能。

## 模拟问答

按风险而非按章节准备问题：

| 类型 | 示例 | 回答结构 |
|---|---|---|
| 问题价值 | 为什么这个问题值得做 | 场景证据、影响、研究缺口 |
| 选题比较 | 与现有方法有什么区别 | 公平比较、条件、贡献边界 |
| 方法选择 | 为什么不用另一方案 | 选择标准、成本、风险和验证 |
| 实验公平 | 基线是否足够强 | 基线来源、复现情况、限制 |
| 指标合理性 | 为什么用这个指标 | 构念、计算方式、补充证据 |
| 数据外部效度 | 结论能否推广 | 样本范围、偏差、限定条件 |
| 负结果 | 某些条件为何失效 | 诊断过程、解释、已验证边界 |
| 创新性 | 核心贡献是什么 | 一条可验证贡献，不堆功能 |
| 工程性 | 系统能否实际使用 | 运行条件、稳定性、局限 |
| 学术规范 | 数据、引用和工具如何使用 | 授权、记录、披露 |

不会答时，明确说明“目前没有这项证据”，给出最接近的已有结果和补充验证路径。不要把猜测包装成确定结论。

做三轮模拟：

- 10 分钟完整叙事：检查逻辑；
- 5 分钟压缩：检查优先级；
- 3 分钟电梯陈述：检查能否抓住核心。

每轮记录被追问超过两次的位置。这些位置通常就是论文证据或表达最薄弱之处。

## 最终交付包

以学校清单为准，通常检查：

- 最终论文及格式审查记录；
- 查重/学术规范材料；
- 答辩 PPT 和备份版本；
- 演示视频或离线演示包；
- 源代码、模型或作品文件；
- 数据或结果说明，符合保密要求；
- 项目说明、运行方式和依赖；
- 图表源数据与生成脚本；
- 必要表单、签字和命名规范。

提交前用声明—证据映射表做最终检查：

```bash
python3 scripts/audit_evidence_map.py path/to/claim-evidence-map.csv
```

确认所有 supported 声明都有可定位证据；partial 和 unsupported 声明已经缩小表述、补充证据或转入局限。脚本只检查表格结构和状态，不代替对论文与原始证据的人工核对。

最终提交前还必须确认：

- F1 公式审查、C1 代码审查和 P1 论文审查都对应当前版本；
- 没有未关闭的 P0；
- P1 已关闭，或按独立审查技能允许的条件记录了复审要求；
- 答辩使用的关键数字和图表都能回到审查过的证据。
