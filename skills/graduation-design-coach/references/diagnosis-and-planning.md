## 目录

- 最小诊断

## 最小诊断

用已有材料完成诊断表。缺失信息不得超过三项关键问题。

| 维度 | 需要知道 | 为什么会改变方案 |
|---|---|---|
| 硬期限 | 提交、盲审、答辩日期 | 决定范围、实验轮次和写作时间 |
| 学历与专业 | 本科、硕士；工科、人文社科、艺术等 | 决定成果形式和评价标准 |
| 强制交付 | 论文、系统、作品、问卷、专利、演示等 | 决定主线与验收物 |
| 当前证据 | 题目、方案、原型、数据、结果、草稿 | 决定不能跳过的前置工作 |
| 资源 | 数据权限、设备、被试、算力、经费 | 决定能否开展关键实验 |
| 导师约束 | 指定方法、题目、格式、阶段检查 | 决定可调整空间 |
| 风险 | 最大未知或最担心失败之处 | 决定先验证什么 |

输出一个简短的“当前判断”，包括：

- 当前阶段；
- 最可能阻塞毕业的单一问题；
- 推荐优先解决它的理由；
- 尚未确认的假设。

## 阶段分类

| 阶段 | 可观察特征 | 下一门槛 |
|---|---|---|
| 探索 | 只有兴趣方向或宽泛领域 | 形成可研究的问题 |
| 收敛 | 有候选题目，但边界、数据或指标不清 | 通过一页范围契约 |
| 设计 | 问题清楚，方法或评价协议尚未成立 | 完成可执行方案与预实验计划 |
| 构建 | 方案已定，核心链路尚不可运行 | 跑通最小可行原型 |
| 验证 | 原型可运行，尚无可信结果 | 获得第一组有效测量 |
| 整合 | 有结果，但结论、图表和论文尚未闭环 | 建立声明—证据映射 |
| 答辩 | 论文基本完成，需要压缩叙事和应对追问 | 完成演示与模拟答辩 |

阶段不是按时间名称划分，而是按证据判断。不要根据“已经写到第 3 章”推断进入整合阶段。

## 从答辩日期倒排

先扣除不可用时间和缓冲，再排里程碑：

1. 预留总时长的 15%–20% 作为整合、返工和行政流程缓冲。
2. 把“正式实验全部结束”放在论文主写作之前。
3. 把“最小可行实验”提前到大规模实现中段，不等系统全部完成。
4. 每周至少安排一个可验证产物，避免连续数周只有“继续开发”或“继续阅读”。
5. 如果学校有开题、中期、预答辩等硬节点，以其为外部里程碑。

计划表至少包含：

| 里程碑 | 截止周 | 验收证据 | 依赖 | 失败预案 |
|---|---|---|---|---|
| 题目范围冻结 | W2 | 一页范围契约 | 导师确认 | 保留两个可收缩选题 |
| F1 公式审查通过 | W4 | 独立审查报告与问题表 | 方法版本冻结 | 缩小方法或补证假设 |
| 评价协议冻结 | W4 | 基线、指标、数据方案 | 数据访问 | 改用小规模案例研究 |
| 核心链路跑通 | W8 | 端到端演示记录 | 技术路线 | 削减非核心模块 |
| C1 代码审查通过 | W10 | 干净环境复现与独立审查报告 | 代码版本冻结 | 回退实现或补测试 |
| 第一组有效结果 | W12 | 可追溯实验记录 | 原型、数据 | 先做单基线主要实验 |
| 论文证据闭环 | W16 | 声明—证据映射表 | 结果分析 | 收缩结论范围 |
| P1 论文审查通过 | W17 | 独立审查报告与复审记录 | 论文版本冻结 | 延后非核心修改，修复 P0/P1 |

## 范围控制

把范围拆成四层：

- **必须完成**：直接支持核心问题、学校要求和最低毕业标准。
- **应该完成**：明显增强可信度或完整性。
- **可以做**：不影响主线，时间富余时增加。
- **明确不做**：与核心问题关联弱或无法验证。

判断一项功能是否保留，问三个问题：

1. 它支持哪条论文声明或哪个评价指标？
2. 缺少它是否会导致核心实验无法进行？
3. 完成和验证它需要多少时间与依赖？

只增加界面、模块或技术栈，却没有新增可测量价值的内容，默认放入“明确不做”。范围收缩时优先删除“不能形成证据的新功能”，保留“能证明核心贡献的最小实验”。

## 风险管理

为每项风险记录：

- 触发信号；
- 发生概率与影响；
- 最晚处理时间；
- 降险动作；
- 降险无效后的收缩方案。

常见高风险及处理方向：

| 风险 | 早期信号 | 优先动作 |
|---|---|---|
| 数据拿不到 | 权限流程未启动或样本不足 | 在开发前取得样本并做数据可用性证明 |
| 题目没有可测目标 | 只能说“做一个系统” | 把价值转成预测、效率、质量或体验指标 |
| 实验做不完 | 实验依赖所有模块完成 | 设计单模块可验证的最小实验 |
| 技术路线不可行 | 连续两个周期没有端到端结果 | 做技术验证原型或更换路线 |
| 导师目标与时间冲突 | 新增要求不服务于核心问题 | 明确最低交付与可选扩展 |
| 论文没有证据 | 正文先写效果结论 | 冻结结论，先建证据表再补实验 |

## 周度检查

每周只回答五个问题：

1. 本周新增的可验证证据是什么？
2. 与上周相比，哪个里程碑状态发生变化？
3. 当前最大阻塞是什么，最晚何时必须解决？
4. 下周唯一的验收物是什么？
5. 是否需要收缩范围或改变技术路线？

将“完成了多少小时”换成“产生了什么可检查结果”。如果连续两周没有新增证据，不要把原计划顺延两周，而应重新评估范围与路线。
