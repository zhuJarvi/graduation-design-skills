## 论文的证据链

论文不是项目日志，而是一条连续论证：

> 问题真实存在 → 现有工作不足 → 本方法针对不足 → 实验协议公平 → 结果支持有限结论 → 局限不影响核心贡献。

任何章节脱离这条链，都应删除、合并或说明其作用。章节名称可以遵循学校模板，但每章必须承担明确的论证任务。

## 章节功能

典型结构可适配为：

| 章节 | 必须完成的功能 | 常见问题 |
|---|---|---|
| 绪论 | 定义问题、价值和边界 | 背景铺陈过长，问题到最后才出现 |
| 相关工作 | 建立比较框架和研究缺口 | 逐篇摘要堆砌，没有综合比较 |
| 方法/系统设计 | 说明为什么这样设计及如何工作 | 只列技术和界面，没有选择依据 |
| 实验设计 | 说明如何公平检验声明 | 指标、数据和基线不完整 |
| 结果与分析 | 给出证据、误差和解释 | 只报最好结果，不讨论反例 |
| 讨论/局限 | 界定贡献适用范围 | 重复结果或把未做的工作写成计划 |
| 结论 | 回收研究问题并给出有边界的结论 | 出现正文没有支持的新声明 |

学校要求的章节顺序优先。若某章无法承担上述功能，需先补内容逻辑，而不是调格式。

## 声明分类

把论文中的关键句分为：

- **事实声明**：引用文献、标准或可核验资料。
- **设计声明**：说明系统或方法做了什么，对应实现和设计材料。
- **效果声明**：说明性能、效率、质量或体验变化，对应实验结果。
- **解释声明**：解释结果为何出现，需要结果、机制或替代解释排除。
- **推广声明**：说明结论可推广到更广场景，需要代表性证据和外部效度讨论。

“效果显著”“优于现有方法”“用户满意度高”等表述都属于需要明确证据和适用条件的声明。

## 证据映射审查

为每个关键声明记录：

| 字段 | 要求 |
|---|---|
| 声明编号 | 唯一、稳定 |
| 论文位置 | 章节或段落 |
| 声明类型 | 事实、设计、效果、解释或推广 |
| 证据 | 图表、实验编号、案例或文献 |
| 证据位置 | 数据文件、附录、表格或引文 |
| 状态 | supported、partial 或 unsupported |
| 缺口动作 | 补实验、限制表述、删除或标注假设 |

审查规则：

1. 摘要和结论中的每项主要声明必须能回到正文证据。
2. 表格和图中的数字必须能回到原始结果。
3. 比较声明必须确认基线、数据和指标一致。
4. 解释性语言不能超过实验可支持的因果强度。
5. 一处证据不能自动支持多个不同条件下的声明。
6. 未验证内容只能作为假设、计划或局限，不得写成结果。

## 图表与引用

图表应各自承担一个明确信息：

- 图题说明看到什么，不写空泛的“系统结果”；
- 坐标轴、单位、图例、样本量完整；
- 对比图使用统一尺度和评价协议；
- 表格避免只突出最佳值而隐藏方差或失败条件；
- 正文不仅重复数字，还要解释模式、差异和限制；
- 图表数据保留原文件，避免仅保存不可编辑截图。

引用用于支持事实或界定研究现状，不用来替代自己的结果。检查：

- 引文是否真正支持所在句；
- 是否引用原始来源而非二传来源；
- 年份、作者、标题和链接是否准确；
- 是否遗漏与结论相反的文献；
- 参考文献格式是否统一；
- 是否遵守学校对生成式工具和学术诚信的要求。

## 修改顺序

优先修复会改变论证的层级：

1. 研究问题、范围和结论是否一致；
2. 实验是否支持效果声明；
3. 方法、数据和指标是否写全；
4. 章节是否形成证据链；
5. 图表与正文是否对应；
6. 语言、术语和格式是否统一。

不要从错别字开始修改一篇还没有证据闭环的论文。

写作时可采用“证据先行”：

- 先列出要证明的 3–5 条核心声明；
- 为每条声明准备证据和边界；
- 再组织章节与段落；
- 最后写摘要和引言，以确保它们与正文一致。

## 审查输出

论文审查结果按严重程度组织：

- **阻断**：结论无证据、实验不公平、核心章节缺失；
- **重要**：证据表达过强、指标或基线不完整、图表不可追溯；
- **一般**：结构、术语、引用和可读性问题。

每条意见应说明位置、问题、为什么影响论证、建议动作和还需的数据。不要只输出一张泛化的修改清单。
