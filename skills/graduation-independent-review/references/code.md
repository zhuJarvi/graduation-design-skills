# 代码与实验实现审查模式

## 审查目标

确认指定代码版本能否正确、稳定、可追溯地产生论文所需结果，并与规格、公式和实验声明一致。

## 材料核对

审查包至少应有：

- 固定的代码版本或快照；
- 环境和依赖安装方式；
- 主入口、输入输出和预期结果；
- 数据版本、样例数据和许可；
- 测试、运行日志和已知失败；
- 公式或算法说明；
- 论文依赖的图表、指标和结果文件；
- 审查范围与排除范围。

需要下载依赖、外部数据或运行高风险命令时，先遵守当前环境的授权限制，不因审查扩大外部操作范围。

## 干净环境复现

审查者在不依赖作者本机隐式状态的环境中尝试：

1. 安装依赖；
2. 运行默认入口；
3. 使用样例数据跑通核心路径；
4. 比较输出与审查包中的预期结果；
5. 运行已有测试；
6. 记录失败命令、错误和缺失依赖。

在副本或隔离目录中运行可能改写结果的命令。不要修改源文件、覆盖唯一结果或清理作者数据。

## 正确性检查

### 核心逻辑

- 实现是否与公式、规格和论文描述一致；
- 下标、维度、类别映射和单位换算是否正确；
- 数据预处理、归一化和标签转换是否一致；
- 训练、验证、测试是否泄漏；
- 损失、正则化、更新步骤和停止条件是否正确；
- 评估时是否误用训练数据或模型选择数据；
- 汇总是否重复计数、遗漏失败样本或改变单位。

### 测试覆盖

- 典型输入；
- 空输入、单样本和异常值；
- NaN、无穷、除零、溢出；
- 文件缺失、权限错误和依赖缺失；
- 训练/测试划分和固定种子；
- 指标计算和结果汇总；
- 失败路径和错误处理。

测试通过不等于逻辑正确。关键模块仍需人工逐行核验。

## 可复现性

| 项目 | 检查内容 |
|---|---|
| 数据 | 版本、哈希、许可、划分方式 |
| 随机性 | 种子、并行、库版本和不确定性 |
| 配置 | 参数、默认值和与论文设置的对应 |
| 产物 | 模型、中间文件、原始输出和日志 |
| 图表 | 从原始结果到最终图表的可重建链路 |
| 环境 | 依赖锁、运行系统和硬件条件 |

至少重跑一个关键实验或子集。无法重跑时，记录剩余风险和不能验证的论文声明。

## 安全与许可

检查是否包含：

- 明文密钥、口令或令牌；
- 未脱敏个人信息；
- 未授权外部上传或下载；
- 不安全反序列化或不可信输入执行；
- 超出任务范围的网络、文件或设备访问；
- 不固定或来源不明的依赖；
- 许可不允许的代码或数据。

发现疑似凭据时只记录位置和类别，不在报告中复制完整秘密。

## 与论文一致

- 代码版本是否对应论文版本；
- 论文中的方法是否与代码一致；
- 正式结果是否来自保存的配置和日志；
- 基线、数据、硬件和指标是否公平一致；
- 失败样本和处理方式是否披露；
- 论文数字能否从保存结果重建。

## 输出

问题应带文件路径和行号、命令、错误或输出位置、影响和修复方向。P0 包括主流程不可运行、核心实现错误、数据泄漏改变结论、结果无法追溯、严重凭据或隐私风险。
